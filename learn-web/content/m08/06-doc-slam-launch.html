Đọc slam.launch.py

File ngắn nhưng dễ hiểu nhầm nhất của module: nó không mở Gazebo, không spawn robot — nó chỉ "cắm vào" dữ liệu đã có sẵn. Đọc đúng docstring thật sẽ tránh được lỗi phổ biến nhất khi mới học SLAM: mở launch file này trước, rồi thắc mắc vì sao chẳng có gì xảy ra.

Những gì file KHÔNG làm

Khác hẳn các launch file đã gặp từ Module 4 (luôn có IncludeLaunchDescription gọi gz_sim.launch.py + node spawn_robot), atlas_slam/launch/slam.launch.py không đụng gì tới Gazebo. Nó giả định 3 thứ đã tồn tại từ trước, do launch file khác (Module 4-7) tạo ra:

  • /scan — từ LiDAR, Module 6
  • /odom — từ diff_drive_controller, Module 5
  • TF odom → base_footprint — cũng từ diff_drive_controller

Thiếu bất kỳ thứ nào trong 3 thứ này, node slam_toolbox vẫn chạy được (không crash) nhưng không vẽ được gì — một kiểu lỗi "im lặng" dễ khiến người mới tưởng launch file hỏng.

Những gì file làm

  • Include launch file gốc của slam_toolbox (online_async_launch.py) — đây mới là launch file thật sự khởi động node slam_toolbox, Atlas chỉ truyền tham số vào
  • Tham số slam_params_file → trỏ đúng mapper_params.yaml (bài 4)
  • Tham số use_sim_time: true — bắt buộc, vì toàn bộ thời gian trong hệ thống (TF, scan) đều chạy theo đồng hồ Gazebo mô phỏng, không phải đồng hồ tường
  • Mở RViz với cấu hình riêng rviz/slam_toolbox_default.rviz, điều khiển bằng arg rviz:=true (mặc định) / rviz:=false

RViz của module này khác gì Module 3/6/7

atlas_view.rviz (dùng từ Module 3) chỉ có 3 display: Grid, RobotModel, TF — đủ để xem khung xương robot. slam_toolbox_default.rviz thêm 2 thứ mới:

  • Display Map — subscribe /map, vẽ occupancy grid (bài 5) đang được dựng dần
  • Display LaserScan — vẽ trực tiếp từng điểm quét hiện tại, giúp so bằng mắt điểm quét mới có khớp với bản đồ đã có không
  • Panel SlamToolboxPlugin (không phải Display — một panel riêng, góc trái) — nút Serialize/Deserialize Map đã nói ở bài 2/5

Thứ tự chạy đúng — 3 terminal

# Terminal 1 — mở world + robot (Module 4-7, bất kỳ cách nào cho ra /scan + /odom)
ros2 launch atlas_bringup bringup.launch.py world:=maze.sdf
# Terminal 2 — bật SLAM, chờ RViz mở
ros2 launch atlas_slam slam.launch.py
# Terminal 3 — lái robot để có chuyển động cho SLAM "ăn"
ros2 run teleop_twist_keyboard teleop_twist_keyboard

Thứ tự terminal 1 trước terminal 2 không bắt buộc tuyệt đối (ROS 2 topic/TF sẽ tự kết nối khi cả 2 bên đã lên), nhưng mở terminal 2 trước sẽ chỉ thấy RViz trống một lúc, dễ gây hoang mang không cần thiết.

Lưu bản đồ khi đã lái xong

# Terminal mới, SAU khi đã lái xong — đừng tắt terminal 1, 2
ros2 run nav2_map_server map_saver_cli -f maze_map
ros2 service call /slam_toolbox/serialize_map slam_toolbox/srv/SerializePoseGraph \
  "{filename: '/home/you/atlas_sim/src/atlas_slam/maps/maze_map'}"

Cả 2 lệnh phải chạy trong khi slam.launch.py (terminal 2) vẫn đang sống — chúng đọc dữ liệu từ node slam_toolbox đang chạy, không phải từ file nào đã lưu sẵn. Nhớ lại gotcha đường dẫn tuyệt đối ở bài 5 cho lệnh thứ 2.
