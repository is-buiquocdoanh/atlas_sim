Đọc controller.launch.py

File ngắn nhất trong cả module — đúng 4 action — vì nó tái dùng gần như toàn bộ những gì Module 4 đã dựng, không viết lại logic mở world hay spawn robot.

Toàn bộ file

def generate_launch_description():
    control_pkg_share = get_package_share_directory("atlas_control")
    gazebo_pkg_share = get_package_share_directory("atlas_gazebo")

    world_arg = DeclareLaunchArgument("world", default_value="empty.sdf")

    spawn_with_control = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(gazebo_pkg_share, "launch", "spawn_robot.launch.py")
        ),
        launch_arguments={
            "model": os.path.join(control_pkg_share, "urdf", "atlas.control.xacro"),
            "world": LaunchConfiguration("world"),
        }.items(),
    )

    joint_state_broadcaster_spawner = Node(
        package="controller_manager", executable="spawner",
        arguments=["joint_state_broadcaster"],
    )
    diff_drive_controller_spawner = Node(
        package="controller_manager", executable="spawner",
        arguments=["diff_drive_controller"],
    )

    return LaunchDescription([
        world_arg, spawn_with_control,
        joint_state_broadcaster_spawner, diff_drive_controller_spawner,
    ])

Chỉ 1 tham số đổi — cả pipeline Module 4 chạy lại nguyên vẹn

spawn_with_control include thẳng atlas_gazebo/launch/spawn_robot.launch.py (Module 4 bài 5) — world mở ra, robot_state_publisher chạy, robot spawn, /clock bridge — y hệt không đổi gì, chỉ override đúng 1 tham số model: trỏ sang atlas.control.xacro thay vì atlas.gazebo.xacro. Đây là hệ quả trực tiếp của 3 lớp xacro luôn include lẫn nhau (bài 2): đổi lớp cao nhất, lớp dưới tự động theo.

2 spawner — vì sao cần tới 2 node riêng

controller_manager spawner không phải script của dự án — là executable có sẵn trong gói controller_manager, nhận đúng 1 tham số: tên controller cần nạp. Atlas gọi nó 2 lần vì có 2 controller (bài 1): mỗi spawner tự load → configure → activate đúng một controller, đọc tham số tương ứng từ diff_drive_controller.yaml (đã nạp sẵn cho controller_manager qua <parameters> trong atlas.control.xacro).

spawner tự chờ/thử lại cho tới khi service của controller_manager sẵn sàng (được plugin gz_ros2_control tạo ra ngay sau khi Gazebo spawn xong entity) — comment thật trong file nói rõ điều này. Không cần tự thêm TimerAction hay event_handler để chờ đúng thứ tự, dù về mặt launch, spawn_with_control và 2 spawner được khai báo chạy gần như cùng lúc.

Lớp ngoài cùng: atlas_bringup

Có thêm một file nữa, không thuộc package này: atlas_bringup/launch/bringup.launch.py. Toàn bộ nội dung chỉ là include controller.launch.py — không thêm action nào. Lý do tồn tại: gom về đúng 1 package làm điểm vào chính cho cả stack, để các package ứng dụng phía trên (atlas_slam, Module 8 trở đi) trỏ vào atlas_bringup thay vì phải nhớ "muốn chạy mô phỏng thì vào atlas_control". Cả 3 lệnh dưới đây tính đến giờ cho ra kết quả giống hệt nhau:

ros2 launch atlas_gazebo spawn_robot.launch.py        # Module 4 -- đứng yên
ros2 launch atlas_control controller.launch.py        # bài này -- lái được bằng /cmd_vel
ros2 launch atlas_bringup bringup.launch.py            # tên gọi chính thức cho stack mô phỏng

Khác biệt duy nhất là lớp xacro nào được truyền làm model — không phải 3 cách làm khác nhau, mà 3 cách nhìn cùng một pipeline với 3 độ sâu khác nhau.

Thử ngay

ros2 launch atlas_bringup bringup.launch.py world:=maze.sdf

So với ros2 launch atlas_control controller.launch.py world:=maze.sdf đã chạy ở các bài trước — xác nhận bằng mắt: không có gì khác.
